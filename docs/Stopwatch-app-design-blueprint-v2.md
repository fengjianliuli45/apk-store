## 1. 产品一句话

Stopwatch 是一个像秒表一样简单的 AI 健身教练：打开 App，按下开始，看身体、选动作、跟着练、休息时由 3D 角色带你恢复，完成动作后获得同道鼓励。

核心不是“健身数据中心”，而是“打开即练”。

---

## 2. 设计北极星

### 2.1 用户目标

- 新手：不用研究课程，也能快速开始一组适合自己的训练。
- 轻健身用户：每天 5–30 分钟完成可持续训练，不被复杂功能打断。
- 社交型用户：在合适的时刻获得鼓励，但训练时不被社交流拖走。

### 2.2 产品原则

1. 主行为永远是开始训练。
2. 数据围绕行动出现，不做默认 dashboard。
3. 社交是奖励，不是打断。
4. 3D 角色服务训练和恢复，v1 不做复杂宠物养成。
5. AI 建议必须可跳过、可修改、可解释。
6. 外观以现行 Figma 为唯一视觉源；本文不锁定任何视觉风格。
7. 首页只承担开始训练，不承担数据看板；完整数据集中进入独立数据模块。

## 4. 全局信息架构

### 4.1 v1 导航

v1 不使用显性底部 Tab。体验以单线训练闭环为主：

```text
登录 / 入门
  -> 主屏
  -> 计划概览
  -> 训练中
  -> 休息 / 动作完成鼓励
  -> 完成总结
  -> 主屏
```

辅助入口：

- 主屏右上：个人入口，仅放账号、历史、设置。
- 完成页：饮食 teaser。
- 段位升级时：进入升段反馈。

### 4.2 v2 导航

v2 才启用 4 Tab：

| Tab | 名称 | 作用 |
|---|---|---|
| 练 | 训练主流程，保留圆形开始按钮 |
| 附近 | 训练地点地图、收藏、打卡、在这里练 |
| 同道 | 搭子推荐、约练广场、动态 |
| 我的 | 段位、历史、饮食、自拍墙、设置 |

底部导航出现后，“练”仍然是默认第一屏。

## 5. 体验与无障碍约束

这些是产品可用性要求，不是视觉风格：

- 首页、训练页、休息页保持低信息密度；数据页可以更密。
- 单屏最多一个主数字、一个确有比较价值的图表、一组次级统计。
- 计时器、能量和组数使用等宽数字，跳秒时布局不抖动。
- 正文与背景对比度至少 WCAG AA；颜色不能作为唯一状态信号。
- 运动中主要操作触控区域不小于 48dp；肌肉点击区域要有容错扩展。
- 支持系统「减少动态效果」：复杂过场降级为短淡入淡出。
- 核心操作放在拇指可达区域。

## 6. 核心页面

外观、层级和控件造型见 Figma。下列只规定职责、内容和交互。

### 6.1 登录 / 注册

目标：快速进入，不让账号系统抢走第一印象。

内容：品牌名 `STOP / WATCH`、邮箱、密码（可切换可见）、主按钮、登录/注册切换。

交互：

- 新用户注册成功后进入入门问答。
- 老用户登录后进入主屏。
- 错误在输入框下方轻量显示，不弹大窗。

### 6.2 入门问答

目标：给 AI 足够信息生成计划，同时保持对话轻。

结构：顶部进度点；中部一问一答；底部下一步。

问题顺序：

1. 训练目标：减脂 / 增肌 / 塑形 / 体能 / 恢复。
2. 场景：居家 / 街头 / 健身房。
3. 基础身体数据：性别、年龄、身高、体重、可选体脂。
4. 训练经验：新手 / 有基础 / 经常练。
5. 每次训练时长：5 / 15 / 30 / 自定义。

约束：每屏一个问题；数字用步进、滑杆或输入；最后一屏进入「正在生成计划」，不是普通表单提交。

### 6.3 生成计划页

目标：把等待变成可理解的过渡，而不是空白转圈。

内容：3D 人体轮廓；文案「正在为你生成今天的训练」；底部当前处理项（匹配场景 / 选择动作 / 估算休息）。

约束：

- 不显示技术细节。
- 超过 8 秒提供「先用默认计划开始」。

### 6.4 主屏

目标：打开即练。

结构：

```text
上方：状态 / 个人入口
中间：圆形开始按钮
按钮周围：两项个人数据
底部：极轻提示或当前计划摘要
```

| 元素 | 内容 | 交互 |
|---|---|---|
| 开始按钮 | 文案「开始」 | 进入计划概览 |
| 运动天数 | 如 `12 天` | 进入训练频率详情 |
| 消耗能量 | 如 `8,420 kcal` | 进入能量详情 |
| 个人入口 | 头像 / 段位标识 | 进入我的 |

约束：

- 不展示计划列表、社交动态、饮食、商城。
- 首页不增加第三、第四项统计。

### 6.4.1 每日开场 / 运动部门入部仪式

目标：把用户从日常状态切换进训练状态，最终落到「开始」。

设定：用户是运动部门新成员；AI 前辈负责把人从拖延里拉出来。气质是青春社团喜剧：热闹、被拽着走，但不羞辱。

结构，控制在 5–8 秒：

1. 待机。
2. 前辈闯入，打断拖延。
3. 闪过今日肌群、预计时长、段位进度。
4. 一句短口号。
5. 收束到圆形「开始」按钮。

示例台词：

- `新人，别装没看见，今天轮到你练腿。`
- `前辈建议：先开始，后后悔。`
- `别紧张，我们部门传统就是先练再解释。`

频率：

- 首次使用：完整版。
- 日常：不默认强播；关键节点 3–5 秒短版。
- 可跳过，跳过文案无负罪感。
- 长期用户降频：连续第 7 天、升段前、久未回归再出现。

不直接复制特定动漫角色、台词、画面或音乐。开场与陪同语音共用同一角色人格。

### 6.5 计划概览

目标：让用户看懂今天练哪里，并能改动作组合。

结构：

```text
顶部：训练名称 + 总组数 / 预计用时
上半屏：3D 人体肌肉图
下半屏：训练摘要或当前肌肉的动作列表
底部：确认开始
```

默认：完整人体；今日肌群可辨认；下半屏给出目标、总组数、预计时长、消耗估算；提示「点击肌肉查看动作」。

点击肌肉后：镜头聚焦该部位；其他部位弱化；下半屏改为该肌肉动作列表。

动作项：勾选、动作名、肌群、组数/次数、难度、组数步进、替换。

确认开始后进入训练。修改动作时总组数和预计时间自动更新。

### 6.6 训练中

目标：用户只关注当前动作和当前组。

结构：顶部动作名 + 组数；中部 3D 演示（无资产时用视频/GIF）；下部大计时；底部「完成本组」。

信息不做中央信息卡，沿 3D 舞台边缘作为 HUD。

状态规则：

- 同一动作还有下一组：完成本组 → 3D 休息。
- 当前动作全部组数完成且不是最后动作：先鼓励卡片，再休息。
- 最后动作完成：直接完成页。

Unity 教练会话额外状态（与 Figma `162:28`–`162:31` 对齐）：

| 状态 | 职责 |
|---|---|
| Ready | 展示动作、组数、站位、视角、开始；可切换男女教练 |
| Active | 教练演示、姿态提示、计时、次数、暂停 |
| Paused | 画面保留，按钮改为继续，动画暂停 |
| Rest | 头顶倒计时；只留下一组 / 跳过 / +30 秒 |
| Rest Last 5s | 预演下一动作；头顶「动作名 · 秒数」 |
| Completed | 完成结果和再次训练 |

训练中交互：

- 暂停：Active / Paused 切换。
- 长按 1.2 秒结束，避免运动误触。
- 跳过休息：立即下一组。
- `+30 秒`：延长休息并回到放松演示。
- POC 可点击教练区域记一次；接入姿态识别后改为识别事件。

教练切换：只在 Ready 和设置里出现；Active / Rest 不出现。切换只换 Avatar 与语音，不重置进度。两位教练共用 Humanoid 动作库。

### 6.7 动作完成鼓励卡片

目标：一个动作全部组数完成后给情绪奖励，不打断每一组。

触发：

- 只在同一动作全部组数完成后出现。
- 组间休息不出现。
- 最后一动完成后不出现。
- 连续跳过 2 次后，本场不再展示。

交互：

- 双击卡片任意处点赞。
- 点头像看昵称、段位、最近训练、共同目标、关注。
- 点卡片外跳过，进入休息。
- 点赞后可提示「也拍一张鼓励下一个人？」：稍后 / 拍一张。
- 不放显眼点赞按钮；不强迫自拍；自拍发布前必须预览。

### 6.8 3D 休息页

目标：帮用户恢复，并在最后 5 秒准备下一组。

只保留两个区域：头顶文字、3D 角色。

| 阶段 | 头顶文案 | 角色 |
|---|---|---|
| 默认休息 | `休息 28` | 呼吸 / 放松 / 肩颈 / 轻拉伸 |
| 最后 5 秒 | `下一组：深蹲 5` | 切换为下一动作预演 |

倒计时结束自动进入训练中。先改文字，再改动作，避免认知冲突。

头顶文字是跟随角色的空间 HUD，不是普通 2D 浮层卡片。v1 角色只做休息/训练教练，不是宠物。

### 6.9 完成总结

结构：完成文案 → 一个主结果数字 → 摘要（总用时、完成组数、消耗估算）→ 一句具体 AI 评语 → 饮食 teaser → 回主屏。

约束：不做复杂趋势图；不强迫分享；饮食在 v1 只做 teaser。

### 6.10 升段

触发：阶段目标完成或重新评估后满足升段条件。

要求：时长 6–8 秒，可跳过；空数据走短版；跳过文案无愧疚。段位是身份标签，不成为整页主题，也不改掉主行为。

### 6.11 饮食模块 v1.1

入口：完成页 teaser；我的页饮食记录。

页面：拍照、识别结果（可改）、当日时间线、摄入 vs 消耗、下一餐建议（可换一个）。

v1 不把饮食放进主导航。

### 6.12 数据

集中承载完整训练数据，避免首页和训练流变成仪表盘。

视图：总览、训练、身体、恢复、营养（v1.1 开放完整能力）。

首屏一个主数字 + 一个有比较价值的趋势；其余指标行式进入详情。数据不足时说明还缺什么，不用空图表填满。

### 6.13 我的

v1 是轻入口，v2 升级为 Tab。

首屏：昵称、训练天数（唯一主数字）、当前目标、数据 / 历史 / 饮食 / 自拍墙 / 设置入口。段位只作身份，不作视觉中心。

### 6.14 附近 v2

上方：城市 / 搜索 / 筛选。中部：地图。下方：地点详情。

地点信息：名称、距离、类型（公园 / 单杠 / 健身房 / 跑道）、适合动作、今日打卡人数。操作：在这里练 / 收藏 / 约搭子。

隐私：进入附近页再要定位；可手动选城市；不显示精确位置。

### 6.15 同道 v2

分段：推荐搭子、约练广场、动态。

搭子：头像、昵称、段位、距离范围、目标匹配、最近训练、邀请 / 关注。  
约练：地点、时间、目标、强度、人数上限、发起人。

v2 不做自由私信。邀请文案 AI 生成但可编辑。支持举报、拉黑、取消约练。

### 6.16 商城 v2

训练补给建议，不是电商。入口在完成页、饮食页、我的页。商品需写推荐原因。不做购物车、支付、物流。避免焦虑式推销。

### 6.17 设置

- 账号：邮箱、退出。
- 训练：默认休息时长、单位、声音、默认教练。
- 隐私：定位、动态可见范围、拉黑。
- 通知：训练、约练、点赞。
- 数据：导出、删除账号。

## 7. 关键流程

### 7.1 首次使用

```text
注册 -> 入门问答 -> 生成计划 -> 主屏 -> 开始 -> 计划概览 -> 训练
```

### 7.2 日常训练

```text
打开 App -> 开始 -> 3D 肌肉计划 -> 调整动作 -> 确认开始
  -> 当前动作当前组 -> 休息 ->（动作全部组数完成时）鼓励 -> 完成总结
```

### 7.3 鼓励闭环

```text
一个动作全部组数完成 -> 鼓励卡片 -> 双击点赞 / 点头像关注 / 点外部跳过 -> 3D 休息
```

### 7.4 休息闭环

```text
完成本组 -> 3D 角色带放松 -> 剩余 5 秒展示下一组 -> 自动进入下一组
```

## 8. 3D 资产策略

外观、材质和灯光跟 Figma / Unity 场景，不在本文规定。

### 8.1 v1 最小资产

| 资产 | 用途 | 数量 |
|---|---|---|
| 3D 人体肌肉模型 | 计划概览点击肌肉 | 1 |
| 训练 / 休息教练 | 动作演示与恢复 | 1（可切换男女） |
| 基础动作动画 | 训练中 / 休息最后 5 秒 | 3–5 |
| 放松动作动画 | 休息阶段 | 3–5 |

### 8.2 边界

- 训练示范模型与肌肉选择模型分开，解剖模型不承担陪练。
- Unity 只承载肌肉选择、动作演示、休息教练；导航、文字按钮、无障碍由原生层负责。
- Android Compose / iOS SwiftUI 负责业务 UI；先独立验证 Unity 场景，再嵌入原生。
- 场景需要可读的落地关系，避免角色看起来在漂。
- 缺少动作资产时不得拿其他动作冒充；验证用程序化回退必须可辨认。

### 8.3 教练切换资产

男女教练共用 Humanoid 与同一套 AnimationClip。女性教练若未导入，Ready 页隐藏切换入口，不阻塞训练。

## 9. 交互节奏

具体动效形态以 Figma 为准。产品层只锁行为节奏：

- 点击肌肉：镜头 300–500ms 聚焦；信息晚 80–120ms 出现。
- 完成本组：按钮有确认反馈，计时短暂锁定；不播全屏庆祝。
- 休息最后 5 秒：先换文案，再换动作。
- 关键交互伴随轻触觉；错误、完成、倒计时节奏不同。
- 训练中单次反馈尽量不超过 500ms。
- 开启减少动态效果后，过场降为 150–200ms 淡入淡出。

## 10. 功能组件清单

下列是产品组件，造型从 Figma 取。不要实现旧文档里的视觉专用件（如角标框、发丝行、舱门过场）。

基础：主圆形开始按钮、主按钮、图标按钮、分段控件、步进器、头像、状态标记、主数字、3D 视口、动作列表项、底部弹层、Toast。

## 11. 内容语气

短、具体、不油腻。

### 11.1 陪同健身语音

角色是「注意力导航员」：可嘴碎、可吐槽，但站在用户这边，把注意力拉回身体、节奏和当前任务。

结构：底层是呼吸/步频/姿态锚点；中层是下一小段任务；表层才是人格。不要持续说话。

可以：`脚步轻一点。呼吸拉长。现在只管这 30 秒。`  
不可以：羞辱式激励（「你太弱了」「别废物」）。

户外优先安全：低频、单耳/骨传导友好，复杂路口降低密度。目标是练出用户自己的节奏，而不是离不开语音。

### 11.2 界面文案

- 主屏：`开始`
- 计划概览：`今天练上半身`
- 肌肉提示：`点击肌肉查看动作`
- 训练中：`第 2 / 4 组`
- 休息：`休息 28`
- 最后 5 秒：`下一组：深蹲 5`
- 完成：`Nice work` / `训练完成`
- AI 评语：具体一句，如「今天腿部完成度很好，下次可以把休息缩短 5 秒。」

避免：「燃爆全场」「马上逆袭」「不练就废了」和长段解释。

## 14. 产品技术架构

### 14.1 跨平台边界

- `shared`：Kotlin Multiplatform。领域模型、规划用例、训练状态机、Repository、序列化、跨端状态。
- `androidApp`：Kotlin + Jetpack Compose。导航、权限、通知、传感器、原生 UI。
- `iosApp`：SwiftUI 调 shared，不追求像素级复用 Compose。
- Unity：受控 3D 子模块。只负责渲染、动画、射线；产品导航、文字、按钮、无障碍归原生。

### 14.2 规划引擎

- Python `fitness-planner` 先当规则基准和测试预言机，输出可版本化计划 JSON。
- UI 只经 `PlannerGateway` 取计划，不直接依赖 Python 结构。
- 确定性规则逐步迁到 shared Kotlin；需频繁迭代的推理可留后端。
- 每份计划记录输入快照、规则版本、结果和调整原因。

### 14.3 数据与设备

- 计划、记录、偏好 offline-first；没网也能练完。
- 账号、社区、地图、跨设备同步走服务端；网络失败不阻塞训练。
- 硬件统一 `SensorGateway`，输出姿态、心率、连接状态，不侵入状态机。
- 姿态校正第一阶段只给安全、可解释提示；低置信度不强制判错或中断。

### 14.4 实现约束

- 核心页面不用 WebView。
- Figma 与 Three.js Demo 不是生产运行时。
- 视觉 token 从现行 Figma 导出，再映射到 Compose / SwiftUI / Unity；本文不定义 token 表。
- Android 与 iOS 可用平台原生导航和输入，但必须共享页面意图与状态机。
