## 1. 产品定义

Stopwatch 是一款以真实训练执行为主线的双平台健身应用。可切换的男性/女性专业健身教练负责动作、安全、节奏和训练处方；语音核心负责低阻力命令入口，并在用户可靠完成第一阶段后孵化为个性化陪伴宠物。

首发体验目标：用户不需要先维护大量数据，即可快速开始训练；训练过程自动记录；突发情况可以立即暂停或结束并保存；阶段进步使用可复测证据判断，而不是依靠打卡时长、单日体重或估算热量。

### 1.1 产品原则

1. **训练优先**：开始训练永远是首页最强操作，社交、宠物和数据补录不能争夺首要注意力。
2. **默认低阻力**：系统自动采集能自动得到的数据；身体测量和非必要反馈允许跳过。
3. **专业与陪伴分工**：男性/女性教练都保持可靠、克制和同等专业；宠物承担情绪反馈和个性化陪伴。
4. **进步必须可信**：阶段达成由确定性规则和可复测数据决定，大模型不能直接解锁。
5. **安全动作优先**：暂停必须比继续、结束、对话或动画更快生效。
6. **离线可训练**：本地训练不依赖网络，云端负责备份与跨设备恢复。

## 3. 首发信息架构

### 3.1 一级导航

首发保留五个一级目的地：

| 入口 | 用户任务 | 首发权重 |
|---|---|---|
| 训练 | 查看今日状态、开始/继续训练、调用语音核心 | 最高，默认首页 |
| 计划 | 查看阶段目标、周计划、训练日历和复评 | 高 |
| 社区 | 查看和发布训练动态 | 中，不硬锁 |
| 数据 | 查看训练趋势和阶段证据 | 中，避免文字堆叠 |
| 我的 | 账号、历史、隐私、设备与偏好设置 | 基础 |

当前代码中的导航命名和排列需要在逐屏定型时与上述结构核对；不因为社区开放而提高它在训练首页的视觉权重。

### 3.2 核心用户旅程

```text
进入应用
→ 可跳过登录先体验
→ 选择训练目标和必要基础信息
→ 生成四周第一阶段计划
→ 首页一键开始训练
→ Unity 专业教练演示与指导
→ Flutter 自动保存组次和状态
→ 训练后一次快捷强度反馈
→ 阶段复评
→ 达成后语音核心孵化为宠物
→ 创建下一阶段目标
```

登录用户可跨设备备份和恢复；未登录或断网时不阻止本地训练。

## 4. 视觉语言

### 4.1 总体气质

使用“安静的未来训练舱”：冷静、明亮、空气感强，科技感来自空间、信息精度、圆形状态和克制动效，不使用黑橙电竞 HUD、复杂霓虹边框或手游式奖励堆叠。

### 4.2 现行色彩

| Token | 色值 | 用途 |
|---|---|---|
| Brand Green | `#BAFF00` | 开始训练、当前主操作、明确选中状态 |
| Ink | `#0D1112` | 主要文字、图标、结构线 |
| Muted Ink | `rgba(13,17,18,0.56)` | 辅助说明和次级元数据 |
| Gradient Top | `#E5F0F0` | 冷白/浅青灰环境顶部 |
| Gradient Mid | `#C7D4CF` | 环境中层 |
| Gradient Bottom | `#EDE8D9` | 暖灰环境底部 |
| Cardio Blue | `#C1EAF5` | 有氧分类和非警示辅助状态 |
| Danger | `#E5484D` | 明确错误或危险，不用于普通停止操作 |

Brand Green 只服务最重要的当前动作。首页的社区、宠物线索、拍照和辅助入口不得同时使用同等级高亮。

### 4.3 字体

- `Inter`：中文正文、按钮、标题和长文本。
- `JetBrains Mono`：计时、数据、状态码和短元信息。
- `Chakra Petch`：品牌字标及少量仪表式强调。
- 数字必须使用等宽布局，避免倒计时和训练数据跳动。

### 4.4 形状与材质

- 圆形：训练主操作、语音核心、状态进度和宠物收纳形态。
- 大圆角卡片：训练摘要、计划、社区内容和设置分组。
- 胶囊：短状态、筛选、低风险快捷操作。
- 背景使用低对比渐变与轻微点阵；正文区域保持足够清晰，不把毛玻璃用于高密度信息。
- 阴影只表达浮层层级，不承担装饰性发光。训练主按钮可有受控的青柠光晕。

## 5. 核心组件

### 5.1 训练主环

- 同时表达今日训练入口和阶段内进度，不显示无来源的装饰百分比。
- 空闲时主文案为“开始训练”；存在可恢复训练时改为“继续训练”。
- 环形进度必须有文字等价信息，不能只依赖颜色或弧长。

### 5.2 语音核心／宠物蛋

- 组件由“圆形语音核心 + 下方字幕区”组成；横向区域只承载转写、状态和助手回复，不是语音助手本体。
- 待机时以圆形核心为主要视觉，字幕隐藏或只显示一句短提示；长内容最多预览 2～3 行，点击后展开。
- 聆听时圆周波形配合用户语音转写；处理中使用克制呼吸/旋转和状态字幕；回复时下方逐步显示助手内容。
- 孵化前只使用系统提示音。
- 聆听时以圆周波形表达，不出现眼睛、裂纹或宠物轮廓。
- `pet_hatchling` 后，同一圆形载体完成孵化并成为宠物入口。
- 孵化后圆形核心内部变为宠物收纳形态，收起、聆听、思考和说话仍保持同一位置及同一字幕区，避免新增悬浮按钮。
- 专业模式减少表情和主动打扰；个性化模式允许更多陪伴反馈。

### 5.3 专业教练舱

- Unity 男性/女性教练负责动作示范、站位、安全提示、节奏和恢复引导；两者使用同一训练计划、能力范围与安全标准。
- 首发必须完成男女切换；当前资产制作顺序为男性优先，女性角色、声音和动作资产在首发验收前补齐。
- 性别选择只改变角色外观、声音和对应动画资产，不改变训练质量、功能权限或专业等级。
- Flutter承载导航、关键文字、暂停/停止、无障碍和训练业务状态。
- 教练、语音核心和宠物不能同时抢夺对话主导权；训练中安全指令优先。

### 5.4 暂停与结束

- 暂停始终可见，一次点击立即冻结动作、计时、休息倒计时、动画和预告。
- “结束并保存”始终可达但低强调，默认长按 1.2 秒；无障碍模式使用二次点击确认。
- 暂停页主次顺序：继续训练 → 结束并保存 → 紧急帮助。

## 6. 关键页面与状态

### 6.1 训练首页

必须包含：品牌/状态、今日训练计时或准备状态、训练主环、低干扰语音核心、辅助入口和底部导航。

状态：无计划、计划生成中、今日休息、准备训练、活动训练、已暂停、存在可恢复训练、今日完成、离线、同步等待。

约束：不展示宠物锁、孵化倒计时、“还差几次”或强制身体数据任务。

### 6.2 训练准备

展示动作名称、当前组/总组数、站位提示、视角切换、教练性别切换和“开始训练”。首发正式版本中男女选项都必须有效；开发阶段尚未接入女性资产时可标注内部占位，但不得以无效控件进入首发版本。

### 6.3 动作进行中

展示动作、当前组、目标次数、实际次数、计时、暂停和必要姿态提示。低置信度姿态判断只提示复核，不强制判错或中断。

### 6.4 组间休息

展示大号倒计时、下一组、恢复提示、“+30秒”“跳过休息”和暂停。暂停与组间休息是两个不同状态；暂停时休息倒计时必须冻结。

### 6.5 停止后总结

首屏只展示“本次训练已保存”、完成组数、有效时间，以及“返回首页 / 稍后继续”。停止原因是可跳过的快捷选择；身体不适会添加安全标记，但不生成诊断。

### 6.6 阶段目标与复评

面向用户优先展示具体进步，例如“深蹲同重量多完成 2 次”，内部百分比不作为主文案。身体数据是可选增强证据，缺失时使用训练表现路径；数据不足显示“继续观察”，不显示失败。

### 6.7 宠物孵化

阶段成果总结完成后，原语音核心进入孵化。动画允许跳过且只自动播放一次；首次人格化语音在孵化完成后出现。随后提供“取名字 / 稍后再说”，命名不得阻塞返回首页。

### 6.8 计划

展示阶段目标、当前中周期、今日安排和下一次复评。避免用复杂模型分数压迫新手；详细训练证据放入二级页面。

#### 6.8.1 2026-09-02 规划引擎与后端对齐修订

本节以仓库 `main@6b4739be72981f98ab652bfba15eace89e5fe9c0` 为实现基线。字段来源为：

- `flutter/lib/planner/models.dart`、`mesocycle_planner.dart`、`recovery_planner.dart`、`check_in_engine.dart`；
- `backend/packages/contracts/openapi.json` 与 `backend/packages/contracts/README.md`；
- `backend/apps/api/STOPWATCH.md` 中 profiles、plans、workouts、sync 与 body-logs 的现行能力。

界面必须区分三个概念，不再用一个“周期”标签混在一起：

| 概念 | 用户界面口径 | 对应实现 |
|---|---|---|
| 阶段目标 | `阶段第 2 / 4 周`，默认四周，未达标可延期 | `StageGoal.cycleWeeks`、`requiredSessions`、`outcomeTargets` |
| 中周期 | `中周期 2 / 5 · 累积期`，包含积累周和减载周 | `Mesocycle.currentWeek`、`lengthWeeks`、`WeekPlan.phase` |
| 计划版本 | `计划 v3`，采用调整后生成新版本 | 后端 `training_plan` + 不可变 `plan_version` |

计划概览首屏的信息层级如下：

1. 顶部只显示阶段周次，避免与中周期长度混淆。
2. 日历同时区分训练、恢复轻日与完全休息；恢复轻日不是失败或漏练。
3. 中周期卡显示当前阶段、目标 RIR、训练量倍率和预定减载周；减脂用户在减载周出现饮食休整提示。
4. 今日训练卡显示预计用时、动作数、目标 RIR、总组数和可用时的绝对负荷；徒手动作显示当前动作变式，不伪造公斤数。
5. “计划依据”用两行短结论解释训练频率、课时容量、恢复排程和伤病限制，详细模型字段进入二级页。
6. 页面底部使用安静状态显示“本地已保存 / 云端已同步”；断网时改为“本地已保存 / 等待同步”，不得阻止开始训练。

二级“计划详情”按需展示以下内容，不全部堆在首屏：

- `frequencyPlan`：引擎决定的每周训练次数、单次时长和容量建议；
- `recoveryDays`：mobility、cardio、pump 或 rest 的时长与重点；
- `mesocycle.weeks`：逐周 RIR、训练量倍率、组数覆盖与减载说明；
- `oneRmEstimates` 与动作 `loadKg`：只在数据来源可靠时显示；
- `injuryAccommodations`：已应用的动作排除、替代和安全提示；
- `volumeCoveragePct`、`vsOptimalPct`：用于解释计划取舍，不作为施压用户的评分。

#### 6.8.2 周期复评与新计划版本

周期复评页必须使用规则引擎结论，不把大模型建议伪装成阶段判定。首屏证据优先展示：

- 计划出勤率和有效训练周；
- 相同动作、相近负荷与努力程度下的可比表现；
- 恢复状态和疼痛/伤病安全信号；
- 可选的体重、腰围或体成分趋势；缺失时显示“未记录”，不阻止复评。

引擎结论与界面文案映射：

| `verdict` | 主文案 | 下一步 |
|---|---|---|
| `address_safety` | 先处理安全问题 | 患处动作降负荷或替换，处理后重新评估 |
| `advance` | 阶段达成 | 进入下一中周期，训练量上调一档，达标动作加重 |
| `extend` | 继续观察 | 延长两周或保持容量，补足训练/可比数据 |
| `deload_then_retry` | 先减载再推进 | 额外减载一周，容量下调 10%，再运行一个中周期 |

“下一周期调整”按实际结果显示 `volumeChange`、逐动作 `loadChanges`、`makeupSessions`、`kcalChange` 与徒手动作进阶；没有变化的项目不占用主视觉。

主操作使用“采用新计划 · vN”。采用后：

- 端上先保存新的计划 JSON 和输入快照；
- 后端通过 `POST /api/v1/plans` 追加不可变版本，保存 `plannerVersion`、`inputSnapshot`、`planJson`、`changeReason`；
- 旧版本不得被覆盖，可从版本历史查看并恢复；
- 网络不可用时进入 Outbox，显示等待同步，不重复生成或丢失训练记录。

#### 6.8.4 2026-09-02 Flutter 实现与验收记录

计划与周期复评已按上述信息结构落入 Flutter，视觉沿用现有 App 的冷白浅青背景、黑色高对比文字、圆角卡片和电光青柠主操作，不直接照搬网页稿或另一套组件语言。

已实现：

- 计划概览区分阶段周次和中周期，显示阶段名称、目标、容量倍率、复评日期、RIR、动作数与主项负荷；页脚显示计划版本、规划引擎版本和同步状态。
- 阶段复评由 Dart 规则引擎实际运行，显示出勤、可比表现、恢复和疼痛证据；缺失的负荷/RIR/恢复证据显示“继续观察”或“未记录”，不补造数据。
- “采用新计划”会追加本地不可变版本；恢复旧版本也会追加一个新版本，原记录不覆盖。历史版本抽屉显示版本号、变更原因、引擎版本与同步状态。
- 本地计划优先落盘；配置后端地址与令牌后，使用 `POST /api/v1/plans` 进行最佳努力同步。未配置或离线时保持“本地已保存”，不阻断训练。
- 旧本地计划载入时会规范化到当前 1.8 schema，并修正早期迁移记录中遗留的 1.1 元数据，确保主卡和“当前版本”一致。

验收结果：`flutter analyze` 无问题；Flutter 全量 105 项测试通过；Android 15 / API 35 x86_64 模拟器已复核计划概览、阶段复评和版本历史，无文字裁切或布局溢出。复评样例的完成率为 13%，引擎摘要正确显示“出勤未达标（1/20）”，不再把已完成训练计为 0 次。

当前边界：本地训练日志仍是聚合记录，只能向引擎提供出勤和完成组数；逐组重量、次数、RIR、疼痛与恢复尚未形成结构化采集，因此“表现进步/停滞”结论会保持观察状态。后端客户端和契约已实现并由替身存储测试覆盖，但在配置真实 API URL、认证令牌和可用服务前，不视为真实云同步验收完成。

### 6.9 数据

优先使用趋势、对比和短结论，避免连续文字列表。必须标明数据来源、时间范围和缺失情况；估算热量不得与真实训练成果使用同等视觉权重。

### 6.10 社区

可以直接访问，不要求训练后解锁。首页不主动强化社区；社区内容不使用代谢、增肌速度或减脂速度做公开排名。群体参考必须匿名、同意加入，并显示样本与适用条件。

### 6.11 我的与设置

包含账号与同步状态、训练历史、语音模式、专业/个性化偏好、设备授权、隐私、减少动态效果和数据导出/删除入口。

## 7. 语音与文案

### 7.1 孵化前

- 只使用系统提示音和中性系统文案。
- “暂停、停一下、等一下、停下来”等本地关键词立即暂停。
- “继续”经短倒计时恢复；“结束训练”先暂停再确认。

### 7.2 孵化后

- 用户可以选择专业模式或个性化模式。
- 专业模式优先简短、准确和低频。
- 个性化模式可以体现宠物性格，但安全、动作和计划结论仍受规则层控制。

### 7.3 文案原则

- 不羞辱、不惩罚、不制造连续打卡焦虑。
- 使用“继续观察”而不是“训练失败”。
- 使用“结束并保存”而不是含糊的“退出”或“放弃”。
- 说明补充数据的收益，不显示强迫式缺失清单。
- 医疗和安全风险使用明确边界，不让人格化角色替代专业帮助。

## 8. 动效、触觉与声音

- 动效优先表达状态变化，不用于持续吸引注意。
- 普通彩蛋线索持续约 1～2 秒且无需操作。
- 暂停反馈必须即时，视觉、触觉和声音保持一致。
- 恢复训练前使用短倒计时，避免动作突然启动。
- 减少动态效果模式使用静态光线、字幕和轻触觉替代孵化/过渡动画。
- 系统提示音与宠物人格语音必须可辨别，孵化前不得提前混用。

## 9. 无障碍与安全底线

- 关键文字和控件满足移动端可读性与触控目标要求。
- 所有颜色状态提供图标、文字或形状冗余。
- 长按结束必须有无障碍二次确认替代。
- Unity场景之外保留Flutter关键控制，Unity异常时仍能暂停、保存和结束。
- 紧急表达由本地规则立即暂停，并显示紧急帮助入口；不依赖网络模型。
- 摄像头视频和原始语音默认不上传；健康、照片和群体数据分别授权。

## 10. 数据与跨设备状态的界面要求

- 本地保存成功即反馈，不让用户等待云端完成。
- 同步使用安静状态，不以持续红点制造焦虑。
- 离线训练正常进行；恢复网络后后台重试。
- 计划采用、训练记录和身体数据按同一账户同步；计划版本只追加，不原地覆盖。
- 计划页可以显示当前 `plannerVersion` 与同步状态，但不得把后端 UUID、游标或内部版本键暴露给普通用户。
- 身体日志用于复评趋势时必须标明时间范围；单日体重不得单独触发增减热量或阶段达成。
- 另一设备存在活动训练时，清楚提供“返回查看 / 接管训练 / 等待失效”，不得悄悄覆盖。
- 异常恢复时显示已保存到哪一组，并提供继续或结束。
